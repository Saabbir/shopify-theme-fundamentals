**TL;DR:** Shopify never generates captions automatically — a real VTT file, uploaded via a `file_reference` metafield, is what a `<track>` element actually needs.

[Video Fundamentals](/all-about-videos/video-fundamentals-video_tag-vs-building-your-own-tag/) establishes that captions require building the `<video>` tag by hand, since `video_tag` has no slot for a `<track>`. This page covers where the actual caption file comes from, and the rest of what makes a video component genuinely accessible beyond captions alone.

## Where a caption file actually comes from

Shopify's video processing transcodes an uploaded video into streamable formats (`mp4`, `m3u8`) — it does not generate captions or a transcript from the video's audio. A real `.vtt` (WebVTT) caption file has to be created separately (recorded manually, or generated by a third-party transcription service) and then uploaded to the store.

```liquid
{% liquid
  assign captions_file = product.metafields.custom.captions_vtt.value
%}

<video playsinline preload="metadata" poster="{{ media.preview_image | image_url: width: 800 }}" controls>
  <source src="{{ primary_source.url }}" type="{{ primary_source.mime_type }}">
  {% if captions_file %}
    <track kind="captions" src="{{ captions_file.url }}" srclang="en" label="English" default>
  {% endif %}
</video>
```

A `file_reference`-type metafield (`custom.captions_vtt`, defined once in Admin → Settings → Custom data → Products) is the real, verified mechanism — a merchant uploads the `.vtt` file directly to that metafield, and `product.metafields.custom.captions_vtt.value` returns a real `generic_file` object with a `.url` property pointing straight at the uploaded file. The `{% if captions_file %}` guard matters here specifically: most products won't have a caption file uploaded, and a `<track>` element pointing at a `nil` URL would produce a broken, non-functional track rather than simply omitting captions.

:::note[One VTT file per language, if multiple languages are needed]
A single `<track>` only covers one language — a store supporting captions in more than one language needs one metafield (or a list-type metafield holding several file references) per language, each rendered as its own `<track kind="captions" srclang="...">`. This chapter covers the single-language case; a true multi-language caption system is a bigger content-management decision a merchant and developer need to plan together, not purely a Liquid technique.
:::

## Beyond captions: the rest of an accessible video component

- **A real, descriptive label**, not a generic one — `aria-label="{{ media.alt | escape }}"` on the `<video>` element (or `video_tag`'s automatic `aria-label`, when using that filter) should describe *what the video actually shows*, the same way an image's `alt` text would, not just "video" or the filename.
- **Keyboard access to the custom play/pause button** — since it's a real `<button>` element (from [Play/Pause UI Patterns](/all-about-videos/play-pause-ui-patterns/)), it's keyboard-focusable and activatable by default; verify it also has a visible `:focus-visible` outline matching the rest of the theme's interactive elements.
- **Respecting `prefers-reduced-motion`**, covered already in [Video Loading & Autoplay Strategy](/media-deep-dive/video-loading-and-autoplay-strategy/) — this applies to a custom-UI video exactly the same way it applies to an autoplaying one.
- **Never autoplaying a video with captions hidden by default** — if captions exist, `default` on the `<track>` element (shown in the example above) ensures they display from the start, rather than requiring a shopper to discover and enable a captions toggle buried in the player.

## Key takeaways

- Shopify transcodes uploaded video for streaming; it never generates captions — a real `.vtt` file has to be sourced separately and uploaded by the merchant.
- A `file_reference` metafield is the real, verified way to attach that `.vtt` file to a product, returning a `generic_file` object with a usable `.url`.
- Guard the `<track>` element on the caption file actually existing — most products won't have one, and an empty `src` produces a broken track rather than cleanly omitting captions.
- Accessibility here is more than captions alone: a real descriptive label, native keyboard support on the custom button, and respecting `prefers-reduced-motion` all matter together.
